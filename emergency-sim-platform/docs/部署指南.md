# 部署指南（交付部署同事）

目标：把“重大突发事件交通应急模拟”模块部署到一体化平台服务器，并接入 `traffic-screen` 首页的 **重大突发事件** 入口。

- 前端是**纯静态页面**，计算在浏览器 Web Worker 内完成，**不需要后端即可运行**。
- 服务端求解器（Node.js）是可选项，只有需要在服务器上计算或给其他系统提供计算接口时才部署。

## 0. 拿到的文件

研究人员提供发布包 `emergency-sim-<日期>.tar.gz`（`npm run build && npm run package` 生成，已包含真实数据）。解压后：

```
dist/            ★ 前端（index.html、config.js、assets/、data/）—— 只部署这一个目录即可
server/          可选：服务端求解器
src/engine/      服务端求解器依赖的计算引擎
package.json / package-lock.json
deploy/          nginx 配置示例、Dockerfile
examples/        traffic-screen 接入示例（EmergencySimEntry.vue、iframe-demo.html）
docs/            本文档、接口文档、模型说明
```

> `dist/data/` 中为地块人口、POI、路网等数据，请按数据授权要求在内网传递，不要上传到公开仓库。

## 1. 部署前端（必需）

服务器上已有 nginx（或其他静态 Web 服务）即可，**不需要安装 Node**。

```bash
# 1) 上传并解压
mkdir -p /opt/emergency-sim && tar -xzf emergency-sim-*.tar.gz -C /opt/emergency-sim

# 2) 在平台现有 nginx server 块中加入（完整示例见 deploy/nginx.conf.example）
location /traffic-screen/emergency-sim/ {
    alias /opt/emergency-sim/dist/;          # 注意末尾斜杠
    index index.html;
    location ~* (config\.js|\.json|\.geojson)$ { add_header Cache-Control "no-cache"; }
}

# 3) 生效
nginx -t && nginx -s reload
```

验证：浏览器打开 `https://39.98.51.213/traffic-screen/emergency-sim/`，页面出现“计算过程”面板，3–5 秒后右侧出现优化结果、地图出现烟羽与分区。

- 子路径可以任意（构建产物使用相对路径），改路径时同步修改下文入口地址即可。
- 若平台前端不是 nginx 托管（如 Java/Node 服务的静态目录），把 `dist/` 整体放到其静态资源目录下即可。
- 若站点统一设置了 `X-Frame-Options: DENY` 或 CSP `frame-ancestors`，且采用第 2 节 iframe 方式，需对该路径放开为 `SAMEORIGIN`。

## 2. 接入“重大突发事件”入口（二选一）

### 方式一：直接跳转（改动最小）

traffic-screen 首页“重大突发事件”按钮的点击事件：

```js
window.location.href = '/traffic-screen/emergency-sim/index.html'
```

并在 `dist/config.js` 中设置 `homeUrl: '/traffic-screen/#/home'`，模块左上角会出现“‹ 返回首页”按钮。

### 方式二：平台内路由页面 + iframe（推荐，保留平台路由）

1. 复制 `examples/EmergencySimEntry.vue` 到 traffic-screen 的 `src/views/`（Vue 2 / Vue 3 通用）。
2. 注册路由：
   ```js
   { path: '/emergency', name: 'Emergency', component: () => import('@/views/EmergencySimEntry.vue') }
   ```
3. 首页按钮：`this.$router.push('/emergency')`。
4. 组件属性 `src` 默认为 `/traffic-screen/emergency-sim/index.html`，部署路径不同时修改。

该组件已处理模块发来的消息：`emergency-sim:result`（每次计算完成的结果摘要，可写入平台其他模块）与 `emergency-sim:back`（返回）。

### 传入事故信息

入口跳转/iframe 地址可带 URL 参数，模块打开即按该事故计算：

| 参数 | 说明 | 示例 |
|---|---|---|
| `site` | 预设事故点 | `taihe` |
| `lon` `lat` `name` | 自定义事故点（WGS84）与名称 | `lon=116.494&lat=39.736&name=六环太和桥危化品泄漏` |
| `wind` | 风况预设：`sw2` `sw3` `n2` `e2` `sw5` `sw1f` `sw7` | `wind=sw2` |
| `windSpeed` `windDir` `stability` | 自定义风速 m/s、风向（来向，度）、稳定度 A–F | `windSpeed=4.2&windDir=200&stability=D` |
| `gas` `leak` | 危化品（`氯气`/`氨气`）、泄漏速率 kg/min | `gas=氯气&leak=8` |
| `view` | 初始视图 `overview` `hazard` `supply` `evac` | `view=evac` |
| `autorun` | 是否自动计算 `1`/`0` | `autorun=1` |

例：`/traffic-screen/emergency-sim/index.html?lon=116.494&lat=39.736&name=太和桥事故&wind=sw2&view=hazard`

页面已打开时，父页面还可用 postMessage 下发 `emergency-sim:run`（可带 params）/ `emergency-sim:set`，协议见 `docs/接口文档.md` 第 3 节，可用 `examples/iframe-demo.html` 本地试验。

## 3. 可选：服务端求解器

需要 Node.js ≥ 18。

```bash
cd /opt/emergency-sim
npm ci --omit=dev                 # 只安装运行依赖
PORT=8787 node server/index.js    # 自动读取 dist/data；也可用 DATA_DIR 指定
curl http://127.0.0.1:8787/api/emergency/health
```

常驻运行（systemd 示例 `/etc/systemd/system/emergency-sim.service`）：

```ini
[Unit]
Description=Emergency simulation solver
After=network.target

[Service]
WorkingDirectory=/opt/emergency-sim
Environment=PORT=8787
ExecStart=/usr/bin/node server/index.js
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now emergency-sim
```

nginx 反向代理（与页面同域，避免 HTTPS 页面调用 HTTP 接口被浏览器拦截）：

```nginx
location /api/emergency/ {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_buffering off;      # 计算过程流式回传
    proxy_read_timeout 120s;
}
```

页面左侧“求解器”选择 **服务端求解器** 即走该接口（`dist/config.js` 中 `apiBase` 同域时留空）。其他系统也可直接调用 `POST /api/emergency/simulate?summary=1`，参数与返回见 `docs/接口文档.md`。

> `deploy/Dockerfile` 需要完整源码仓库（会在镜像内构建并运行测试），不适用于发布包。

## 4. 运行时配置 `dist/config.js`

| 配置项 | 说明 |
|---|---|
| `title` / `subtitle` | 大屏标题、副标题 |
| `map.basemaps` | 底图列表，地图右下角“图层”按钮切换（第一项为默认）。默认：深色街道 / 卫星影像 / 标准街道（高德在线瓦片，`gcj02`）/ 无底图。客户端无外网时把 `url` 换成内网瓦片服务；每项可设 `overlayUrl`（注记叠加层）、`darkFilter: true`（浅色瓦片深色化）或 `filter`（任意 CSS filter） |
| `map.coord` | 所有底图共用的坐标系：`gcj02`（高德/腾讯）或 `wgs84`（天地图/OSM 等） |
| `apiBase` | 服务端求解器地址，同域部署留空 |
| `stageDelayMs` | 计算过程每阶段最短展示时长（ms），0 为即时出结果 |
| `autoRun` | 打开页面是否自动计算 |
| `homeUrl` | “返回首页”按钮地址，留空不显示 |

修改后刷新页面即生效，无需重新构建。

## 5. 更新数据

研究人员重新导出数据后：

- 方式 A：重新 `npm run build && npm run package`，整体替换 `dist/`；
- 方式 B：只替换 `dist/data/*.json`。

两种方式都无需重启 nginx；若部署了服务端求解器，需重启 Node 服务（`systemctl restart emergency-sim`）。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 白屏或提示“数据加载失败” | 不能双击 `index.html` 以 `file://` 打开（浏览器禁止加载 Worker 与 JSON），须通过 Web 服务访问；检查 `alias` 路径，确认 `/traffic-screen/emergency-sim/data/facilities.json` 返回 200 |
| 地图无底图（深色背景，只有图层） | 客户端无外网或高德瓦片被拦截（地图右下角会提示“底图瓦片无法加载”），按第 4 节在 `map.basemaps` 中换成内网瓦片；道路、地铁矢量图层不依赖外网，可先选“无底图” |
| 地图上没有道路、地铁 | `data/basemap.json` 不存在：由研究人员运行导出脚本生成后放入 `dist/data/` |
| iframe 内空白 | 响应头 `X-Frame-Options`/CSP 禁止嵌入，改为 `SAMEORIGIN` |
| 服务端求解报错 | 先看 `/api/emergency/health`；nginx 代理需 `proxy_buffering off`；HTTPS 页面不能直接调用 `http://IP:8787` |
| 计算很慢 | 首次计算约 1–3 秒（含路网时稍长）；“计算过程”展示另有每阶段 0.45 秒动画，可把 `stageDelayMs` 设为 0 |
| 浏览器兼容 | 需支持模块化 Web Worker：Chrome/Edge 80+、Firefox 114+、Safari 15+ |
